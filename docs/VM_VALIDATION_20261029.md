# 优化版本的本机 openEuler 验证

2026-10-29，优化分支提交 `f32c5cec356b32e2c5b09314b9145b6af06ae3f6` 已在本机 VirtualBox 的 openEuler 中完成严格编译、功能回归和两套性能对照。这批数据独立于 10 月 26 日的 CI 容器数据，不将两种环境的绝对耗时混在一起比较。

## 环境和运行方式

- openEuler 24.03 LTS-SP3 x86_64，内核 `6.6.0-132.0.0.111.oe2403sp3.x86_64`。
- GCC 12.3.1，VirtualBox 虚拟机配置 2 vCPU、4096 MiB；测量子进程固定到同一个可用虚拟 CPU。
- 两版均使用 `-O2 -g -std=c11 -Wall -Wextra -Wpedantic -Werror`。主要比较均开启完整记录；无记录模式独立保存，不参与完整记录的改善比例。
- 由 oslab 用户运行，不需要 sudo。在新的 `validation-20261029T081843Z-ef1a96/uthread-lab` 目录验证，保留原客户机项目。

主机侧游戏保护驱动冲突处理后，虚拟机从硬盘正常启动。停用 ACE 单独没有解决启动问题；随后临时停止完美世界平台的 MessageTransfer 驱动后启动成功。该启动排查与运行时代码性能分开，不将宿主驱动调整作为代码优化成果。

复现命令，在相同源码根目录执行：

```sh
make check CFLAGS='-O2 -g -std=c11 -Wall -Wextra -Wpedantic -Werror'
python3 -m unittest discover -s tests -p test_reporting.py -v
make perf-check CFLAGS='-O2 -g -std=c11 -Wall -Wextra -Wpedantic -Werror'
make wait-perf-check CFLAGS='-O2 -g -std=c11 -Wall -Wextra -Wpedantic -Werror'
```

## 功能验证

四条命令全部返回 0。C 回归覆盖 EOF、超时、错误 fd、阻塞 fd 拒绝、竞争读者、信号中断、重复初始化、日志扩容/耗尽、CSV 转义、无记录模式、槽位复用、errno 隔离，以及共享 fd 的不同截止时间、等待表压缩、POLLNVAL 和 32 任务轮转回绕。4 项 Python 数据与报告检查全部通过。

冒烟实验中，阻塞读结束前工作任务推进 0 次，事件驱动版本推进 40 次；这只核对功能，不是统计性能结论。
