# 当前实现说明

## 运行时的责任

运行时只管理同一个内核线程中的协作式用户任务。每个任务有独立栈、ucontext、函数与参数，以及 READY、RUNNING、WAIT_IO、DONE 四种状态。

创建任务后进入 READY；调度器选择就绪任务并切入其上下文，状态变为 RUNNING。任务调用 yield 后重新就绪；调用 ut_read 遇到 EAGAIN 时进入 WAIT_IO；I/O 就绪或到期后回到 READY，恢复执行并重新检查 read 的结果。任务函数返回时进入 DONE，通过 uc_link 返回调度器，随后由调度器释放已经退出的任务栈。

## 公平性和等待

轮转模式从上次选择之后开始查找 READY 任务。first-ready 对照每次从数组开头查找，用于演示固定优先选择低下标任务的后果。两者均不能强制抢占不主动让出的任务。

每个调度边界都会检查 poll 事件；有 READY 任务时采用非阻塞检查，没有 READY 任务时阻塞到 I/O 或最近期限。信号中断后重新计算剩余时间，保持原有截止时刻。多个任务等待同一描述符时可能一起被唤醒，真正读取前仍要处理 EAGAIN，不能把就绪通知当作读取保证。

## 观测的边界

运行时事件记录在预分配数组中，结束后再写出。它记录用户级调度与等待，不能代替 Linux 内核调度跟踪。用户任务内部如果直接调用阻塞系统调用，运行时无法在阻塞期间继续安排其他用户任务；这是阻塞对照需要展示的现象。

pthread 对照只记录相同的程序标记，不伪造其内核线程状态。重复测量用统一标记日志核对工作量与读完成前的任务进度；另存用户级状态日志帮助解释机制。内核上下文切换次数与用户级切换次数不可混用。

## 当前限制

最多 32 个任务，任务栈固定 128 KiB，没有保护页；已完成的槽位不在同一次运行中复用。事件上限 131072，溢出会标记并使导出失败。ucontext 依赖具体 Linux/libc，尚未在其他架构验证。还未提供多核用户级调度、抢占、任意阻塞调用拦截、普通磁盘文件异步化或不可信任务隔离。
