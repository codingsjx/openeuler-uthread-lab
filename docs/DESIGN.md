# 当前实现说明

协作取消使用包含 id 与 generation 的任务句柄。代次计数跨 destroy/init 保留，旧句柄不能指向复用槽或下一次运行中的新任务。取消 I/O 等待者时从共享 fd 等待集合移除它、重算方向与期限，再以 ECANCELED 恢复任务；READY 任务的后续 I/O 也检查取消。取消不会自动释放应用 fd 或终止任意计算代码，任务仍需返回并执行清理。

TCP 的可选 reclaim-stalled 策略只在容量满且新连接已提供首字节时，选择实际 I/O 等待且无进展超过阈值的候选。候选限于从未提供过数据的读等待或写侧背压等待；不回收已有交互的普通空闲读者。它最多暂存一个候选 socket，取消旧任务、等待清理完成后再接入。默认 reject 策略保持可用。正常慢连接也可能被回收，这不是恶意检测或服务质量保证。

任务函数可在运行时调用 ut_spawn 创建子任务；32 个活动任务的上限保持不变。任务返回后，由调度器释放其栈，随后其他任务才能复用这个槽。TCP 示例预留一个接收任务并最多容纳 31 个连接任务，容量满时关闭新连接，不堆积应用等待队列；接收任务每次 accept 后主动让出。连接参数的应用槽仅在处理任务即将返回时释放，避免先释放参数却仍继续执行的生命周期冲突。

新增 UT_TRACE_RECENT 模式固定复用最多 256 个事件槽，按时间顺序导出最近窗口，并在覆盖时写出 overwritten 标记。它不承诺完整历史。FULL 模式仍支持增长至既有上限，超过上限会报错；OFF 不分配事件缓冲。旧有完整记录的行为不变。

本版本提供 `ut_write` 与 `ut_accept`，复用等待表及单调时钟期限。每个等待任务保存 POLLIN/POLLOUT 方向；同一 fd 的 pollfd 合并所需事件，唤醒时只恢复方向匹配、发生错误/挂断或已经超时的任务。移除成员后重新合并方向，避免残留 POLLOUT 导致只读等待忙轮询。ut_write 保留部分写入语义；连续写入的整体期限、应用队列上限及 SIGPIPE 处理由调用者负责。

## 运行时的责任

运行时只管理同一个内核线程中的协作式用户任务。每个任务有独立栈、ucontext、函数与参数，以及 READY、RUNNING、WAIT_IO、DONE 四种状态。

创建任务后进入 READY；调度器选择就绪任务并切入其上下文，状态变为 RUNNING。任务调用 yield 后重新就绪；调用 ut_read 遇到 EAGAIN 时进入 WAIT_IO；I/O 就绪或到期后回到 READY，恢复执行并重新检查 read 的结果。任务函数返回时进入 DONE，通过 uc_link 返回调度器，随后由调度器释放已经退出的任务栈。

## 公平性和等待

就绪任务保存在 32 位位图中。轮转模式从上次选择之后取下一个就绪位，到末尾回绕；first-ready 每次取最低就绪位，用于演示固定优先选择低下标任务的后果。两者均不能强制抢占不主动让出的任务。

存在 I/O 等待者时，每个调度边界都会检查 poll 事件；有 READY 任务时采用非阻塞检查，没有 READY 任务时阻塞到 I/O 或最近期限。没有等待者时跳过 poll 准备。信号中断后重新计算剩余时间，保持原有截止时刻。多个任务等待同一描述符时可能一起被唤醒，真正读取前仍要处理 EAGAIN，不能把就绪通知当作读取保证。

只有一个存活任务时，yield 可直接继续该任务，省去无意义的往返切换。状态轨迹中的 same_task 明确标示此情况。调度器维护存活与等待计数，并保存任务 errno。具体实现与同环境对照见 OPTIMIZATION.md。

等待表持续保存，每个 fd 对应一个 pollfd 和等待任务位图，避免逐轮重建及重复提交同一 fd。最近截止时间在成员变化时重算。同一 fd 的读者各自保留超时，部分读者到期不会移除其他读者。移除空组时将末组移入空位，并处理它在本次 poll 中已返回的事件。第二轮实现与对照见 [WAIT_OPTIMIZATION.md](WAIT_OPTIMIZATION.md)。

## 观测的边界

运行时默认开启完整事件记录，缓冲按需增长，结束后再写出。内置事件名以枚举保存，导出时转换为 CSV 字符串。可显式关闭记录，此时不提供事件轨迹，也不允许成功导出空轨迹。它记录用户级调度与等待，不能代替 Linux 内核调度跟踪。用户任务内部如果直接调用阻塞系统调用，运行时无法在阻塞期间继续安排其他用户任务；这是阻塞对照需要展示的现象。

pthread 对照只记录相同的程序标记，不伪造其内核线程状态。重复测量用统一标记日志核对工作量与读完成前的任务进度；另存用户级状态日志帮助解释机制。内核上下文切换次数与用户级切换次数不可混用。

## 当前限制

最多同时占用 32 个活动任务槽位，任务栈至少 128 KiB，按页对齐并在两端设置保护页；保护页不是进程隔离，栈溢出仍可能使进程终止。已完成的槽位可在运行中复用。完整记录事件上限 131072，溢出会标记并使导出失败；最近窗口模式按上述固定上限覆盖。ucontext 依赖具体 Linux/libc，尚未在其他架构验证。还未提供多核用户级调度、抢占、任意阻塞调用拦截、普通磁盘文件异步化或不可信任务隔离。
